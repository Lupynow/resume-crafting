# 岗位匹配：把经历翻译成招聘方看得懂的语言

配合 `SKILL.md` 的「路径 B：审改」使用。

## 一个前提

**简历不是个人经历汇总，是一份岗位匹配说明。**

应届生最常犯的错不是经历少，是**经历写得太散**——课程、社团、比赛、兴趣爱好全堆上去，想着"先把页面填满"。结果招聘方扫完，看不出你和这个岗位有什么关系。

招聘方不会因为你把大学四年写完整了就发面试。**他是在快速扫描"这个人跟我的岗位像不像"。**

## 第一步：从 JD 倒推

写任何定向简历之前，先做这一步：

1. 找 **10 条同类岗位的 JD**（同一个岗位名，不同公司）
2. 逐条圈出**反复出现的词**——工具、任务、能力
3. 回自己的经历里**找证据**

**为什么是 10 条不是 1 条**：单条 JD 带着那个 HR 的个人偏好，10 条的交集才是这个岗位的真实要求。

举例，十条运营岗 JD 里的高频词和对应证据：

| 高频词 | 你需要在简历里给出的证据 |
|---|---|
| Excel / 数据整理 | 用 Excel 整理 300 条报名信息，统一字段格式，检查重复与缺失 |
| 内容表达 / 文案 | 协助公众号选题整理、排版与发布，按周记录阅读量与互动数据 |
| 活动执行 | 负责报名统计、人员通知、现场签到与物料核对，协助完成 200 人规模活动 |
| 数据复盘 | 按周记录数据并输出小结，指出哪类选题互动更好 |

**这不是照抄 JD**，是把真实经历**翻译成招聘方的语言**。JD 写"具备数据整理能力"，你写"用 Excel 整理过 300 条报名信息"——同一个能力，后者可验证。

## 第二步：不同岗位关注什么

同一段经历，投不同岗位要突出不同侧面：

| 岗位类型 | 招聘方在找什么 | 你的经历里该突出 |
|---|---|---|
| 运营 | 数据整理、内容表达、活动执行 | 活动怎么落地、数据怎么记录 |
| 行政 | 资料整理、流程跟进、沟通协调 | 文件怎么归档、多方怎么对接 |
| 客服 | 客户沟通、问题处理、服务意识 | 接待量、问题解决、投诉处理 |
| 销售 / 外贸 | 英语、客户跟进、订单意识 | 客户数量、跟单周期、成交情况 |
| 技术 / 研发 | 编程能力、项目深度、技术取舍 | 为什么这么设计、踩过什么坑 |
| 数据 | SQL / Excel、指标体系、分析报告 | 分析结论、指标怎么定义 |
| 产品 | 需求分析、跨部门协作、数据驱动 | 需求怎么拆、方案怎么推 |
| 职能 / 管培 | 学习能力、跨部门沟通、执行力 | 多线程推进、快速上手新领域 |

### 同一段经历，四种写法

以"组织一场 200 人的校园活动"为例：

- **投运营**：负责报名统计、人员通知、现场签到与物料核对，协助完成 200 人规模活动；活动后按周记录参与数据与反馈
- **投行政**：负责场地对接、物资清单核对与现场协调，协调 5 个部门的参与人员按时到位
- **投客服**：负责 200 名参与者的报名咨询与通知回复，处理临时变更 12 次
- **投市场**：负责活动在校内 3 个渠道的推广文案与投放，报名转化 200 人

**同一件事，招聘方要看的侧面完全不同。** 把经历按目标岗位重新组织，是定向简历的核心动作。

## 第三步：多版本策略

同时尝试几个方向没问题，但不能用同一份简历——**一份什么都写一点的简历，等于在说"我还没想清楚"**。

| 情况 | 做法 |
|---|---|
| 方向相近（如数据分析 / 数据运营） | 一份就够，调整方向标签和措辞侧重 |
| 方向不同（如运营 / 技术） | **分开做**，各自取舍内容，不要折中 |
| 海投（BOSS 直聘、智联等） | 去掉方向标签和页脚，头部用专业名或届别 |

**文件命名**：`姓名-应聘岗位-电话`，例如 `张三-数据分析-13800000000.docx`。

不要用「我的简历最终版」「简历最新版 2」「新建文档」——这类文件名会让招聘方在打开之前就先减一分印象。

## 自检

投递前拿目标岗位的 JD 对着简历问：

1. JD 里的高频词，我的简历里出现了几个？
2. 每一条经历，能不能回答"这条跟这个岗位有什么关系"？
3. 如果把我的名字遮住，这份简历看起来像是一个明确投这个岗位的人写的吗？

第 3 条答不上来，说明还没定向成功。
