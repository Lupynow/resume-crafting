# 追问预演与面试题

两份不同的产出，用途不同，不要混。

| | 追问预演 | 面试题 |
|---|---|---|
| 针对 | **简历上你自己写的每一条** | 目标岗位的**通用题库** |
| 来源 | 从简历反向推导 | 岗位知识体系 |
| 用途 | 防止被自己的简历问倒 | 系统性复习 |
| 篇幅 | 逐条列，10-20 条 | 按类别，每类 5-10 题 |

---

## 一、追问预演

### 生成方法

扫描简历，找出两类"钩子"，每个都要展开：

**钩子 1：技术名词** —— 只要出现具体技术名，面试官就会问选型和实现。

**钩子 2：精确数字** —— 只要出现百分比、倍数、精确数量，面试官就会问怎么测的。

### 四类问法

对每个钩子，按这四类各准备一版：

| 类型 | 问法 | 准备什么 |
|---|---|---|
| **选型** | 为什么用 A 不用 B？ | 对比过什么，各自的取舍 |
| **实现** | 具体怎么做的？ | 关键步骤、参数、代码结构 |
| **数据** | 这个数字怎么来的？ | 测试集构建、评测方法、baseline |
| **边界** | 什么情况下会失效？ | 已知短板、异常场景 |

### 输出格式

按简历顺序逐条列，**直接写成"问题 → 怎么答"**：

```markdown
### 企业知识库系统（示例）

**"暂缓引入向量数据库"这句话**

Q1: 为什么不直接用向量检索？评估过吗？
A: 当时文本资料已有几十万字符，全量入上下文不现实；
   评估后判断当前语料规模用 SQLite FTS5 + 中文分词足够。
   同时设了三条切换条件：文档超 1000 份、同义检索 Top-20 低于 90%、
   跨项目检索明显依赖人工补词。

Q2: 那现在这个规模，BM25 的短板在哪？
A: 概念型查询排序差。基准集里一道问"某原理如何表征设备健康"的题
   排到第 11 位 —— 题干里没有文档中的原词。这是典型的词面匹配短板。

Q3: 基准集怎么建的？会不会太简单？
A: 基准题覆盖公司关系、技术原理、设备配置、客户需求。
   坦白说全是正向题，没有"库里查不到"的负样本，这是我下一步要补的。
   另外题目里有些用了文档原词，可能有偏向性。
```

**注意 Q3 的处理方式**：主动坦白弱点（全是正向题、用了原词），比等对方问出来强得多。

### 高风险清单

以下这些点**几乎一定会被问**，优先级最高：

- 所有百分比、倍数类指标（"提升 80%""命中 100%"）
- 所有"自建/自研"的评测集（怎么建的？有负样本吗？）
- 所有"从 0 到 1"的项目（真的是你从零做的？需求谁提的？）
- 所有偏门的架构决策（为什么用这个不用那个）
- 简历里**写了但你不熟**的任何名词

最后一条尤其重要：**改简历时如果发现某个词用户解释不清，就把它删掉**。写在简历上却答不上来，伤害远大于不写。

## 二、面试题

### 按岗位生成

先确认目标岗位（简历标题里的方向），再按类别出题。以下是常见岗位的框架：

**后端开发**
- 语言基础（Java 集合、并发、JVM / Go 调度器、GC）
- 框架（Spring 生命周期、AOP 原理、事务传播）
- 存储（MySQL 索引与事务、Redis 数据结构与持久化）
- 中间件（MQ 消息可靠性、幂等、顺序）
- 系统设计（限流、降级、分布式锁）

**AI 应用 / 大模型**
- Prompt 工程（结构化提示、Few-shot、约束）
- RAG（分块策略、召回、重排、评测）
- Agent（工具调用、状态管理、失败回退）
- 评测（基准集设计、指标选择、负样本）

**数据 / 算法**
- 数据处理（清洗、特征工程、异常值）
- 模型（选型、调参、过拟合判断）
- 评测（交叉验证、指标选择）
- 工程（数据管道、性能）

**产品**
- 需求分析（用户访谈、优先级）
- 方案设计（流程、边界、验收标准）
- 数据（埋点、指标定义、AB 测试）
- 协作（跨团队推进、干系人管理）

### 生成原则

1. **基于简历内容出题**，不要出通用八股 —— 用户的时间和面试官的问题都围绕简历展开
2. **标注难度层级**：基础 / 进阶 / 场景设计
3. **每题给出"考察点"**，让用户知道面试官在探什么
4. **结合用户的真实项目**：例如他做了知识库，就出"如果文档量增长 10 倍，你的方案要怎么改"

### 输出格式

```markdown
## 大模型与 RAG（进阶）

**Q: RAG 里怎么判断该用向量检索还是关键词检索？**
考察点：是否理解两种检索的适用边界，而不是背概念。
提示：从查询类型（语义型 vs 精确匹配）、语料规模、延迟要求三个维度答。

**Q: 你的分块参数是怎么定的？**
考察点：参数是拍脑袋还是有依据。
提示：如果确实没有系统调过，照实说，并给出你会怎么设计对比实验。
```

## 三、生成后的自检

交付前确认：

- [ ] 追问预演覆盖了简历里**每一个**精确数字
- [ ] 每条"为什么"都有了答案，答不上来的已经反馈给用户
- [ ] 面试题按岗位分类，不是通用八股堆砌
- [ ] 明确了哪些问题用户**当前答不好**（这是最该补的）
- [ ] 如果发现用户解释不清的名词，建议从简历里删掉
